# 出单员下发率指标看板设计规格

## 1. 目标

为广西后援作业中心提供一个本地运行的下发率指标看板。使用者每次上传一份清单后，系统从本地数据库读取出单员名单、组长排除口径、已确认责任规则和指标计算公式，完成筛选、计算和可视化展示。

看板优先服务两个场景：管理人员快速掌握整体考核结果和低分人员；业务人员进入个人明细，追溯下发率、责任清单和审核意见。

## 2. 范围与边界

### 纳入范围

- 上传 `.xlsx` 清单并识别源表字段。
- 在本地持续保存历次上传的原始文件和标准化明细。
- 新上传清单作为增量数据合并到本地累计数据，不删除既往原始数据。
- 以源表“出单时间”识别可选年度和月份。
- 只匹配本地数据库中的出单员名称。
- 自动排除数据库标识为组长的人员。
- 按已确认的出单员责任规则筛选下发清单。
- 按本地数据库中的公式计算每名普通组员的下发率和指标得分。
- 保存计算期间，支持历史期间切换。
- 对未确认的退回审核意见单独进入“待确认意见”，不计入当前结果。

### 不纳入范围

- 不根据投保人、被保险人、机构、业务员等字段认定出单员责任。
- 不在看板内直接修改源表原始数据。
- 不自动把新出现的审核意见判定为下发责任。
- 本阶段不考虑线上部署和多人协同权限。

## 3. 数据和计算口径

### 数据来源

- 用户上传的清单是增量数据来源；本地累计数据是看板查询和历史期间调用的明细来源。
- 每次上传保留原始文件、上传时间、文件名、解析结果和规则版本，便于追溯。
- 新文件通过记录唯一性校验后加入累计明细；同一记录的再次上传不能造成重复计数。唯一性规则为：优先使用“保单号”，保单号为空时使用“投保单号”。
- 原始文件采用只追加方式保存，不因后续更新覆盖。标准化累计层保存当前可计算版本，并关联原始文件和源表行号。
- 出单员名单、组长名单、评分公式、已确认审核意见规则来自本地数据库。
- 页面显示的“总笔数”是按所选期间从本地数据库汇总的“非车保单 + 非车批改”笔数，不使用“半年分母”字样；上传清单行数作为原始数据质量和明细统计另行展示。

### 本地累计和更新流程

1. 上传新清单后先保存原始文件，再执行字段识别、日期解析、人员匹配和责任规则匹配。
2. 按“保单号优先、投保单号补充”的唯一性规则比对，展示本次新增记录、已存在记录、内容发生变化的记录、无法识别记录和待确认意见数量。
3. 用户确认合并后，将新记录加入累计数据；已存在记录按确定的唯一性规则更新标准化版本，并保留变更历史。
4. 看板按累计数据查询任意年度、月份和人员；当前期间结果绑定本次计算使用的数据快照，避免后续上传导致历史结果无提示变化。
5. 既往原始记录可从人员明细、历史期间和原始数据查看入口调用，但统计时只使用累计层中的唯一有效记录。

### 期间选择

- 上传后扫描“出单时间”字段，自动生成文件中实际存在的年度、月份选项。
- 用户手动选择年度和月份，可选择单月或文件覆盖的月份区间。
- 选择变化后，所有 KPI、排名、趋势和明细同步重新计算。
- 无法识别“出单时间”的记录进入数据质量提示，不静默计入其他期间。

### 人员范围

- 仅保留数据库中的出单员名称。
- 组长由数据库人员属性排除，不在普通组员人数、排名、分布和平均分中出现。
- 当前已知排除人员为宋键、梁欣宁，实际实现仍以数据库配置为准。

### 下发清单认定

- 以“退回审核意见”具体内容匹配已确认的出单员责任规则。
- 只有能够区分为出单员操作失误的意见计入下发清单。
- “下发修改，请补充材料再提交”不计入出单员责任。
- 重复投保、保障重叠、调整生效日期、剔除重复人员等意见不计入。
- 未写明具体原因的意见不计入。
- 新意见默认进入待确认状态；用户确认后才影响计算，并作为后续期间的默认规则。
- 其他人员原因、业务员原因、核保人员原因不计入出单员下发清单。

### 评分公式

当前确认的分段规则：

| 下发率区间 | 指标得分 |
| --- | --- |
| 下发率 ≤ 0.9% | 100分 |
| 0.9% < 下发率 ≤ 1.8% | 99-90分线性取值 |
| 1.8% < 下发率 ≤ 3% | 89-60分线性取值 |
| 3% < 下发率 ≤ 5% | 59-1分线性取值 |
| 下发率 > 5% | 0分 |

实际计算时优先读取数据库中的公式配置；页面展示当前使用的规则版本和计算时间，便于追溯。

## 4. 页面结构

### 顶部操作区

- 页面标题：出单员下发率指标看板。
- 年度选择器：只显示上传清单识别出的年度。
- 月份选择器：显示文件中可用的月份或月份区间。
- 上传新清单按钮：打开文件选择、解析和计算流程。

### 一级导航

- 总览：管理人员默认进入页面。
- 人员分析：查看单名出单员的趋势和责任明细。
- 待确认意见：处理新出现、尚未确认的审核意见。
- 历史期间：切换和查看已保存的计算结果。

### 总览页

首屏按以下顺序展示：

1. 普通组员人数、平均指标得分、90分以上人数、60分以下人数。
2. 得分区间分布：99-90、89-60、59-1、0分，显示人数和占比。
3. 重点关注人员：展示得分、下发率和风险状态，重点关注阈值为得分低于60分，0分标记为严重异常。
4. 人员得分排名：排名、出单员、下发率、列入笔数、总笔数、指标得分和状态。
5. 月度下发率趋势：按选定期间展示整体或人员月度变化。

### 人员分析页

- 出单员选择和期间选择。
- 下发率、列入笔数、总笔数、指标得分和当前状态。
- 月度下发率与得分趋势。
- 符合下发清单：保留源表原始口径和退回审核意见，支持查看完整行内容。
- 未计入清单：显示被规则排除的意见及排除原因，便于复核。

### 待确认意见页

- 展示意见文本、出现次数、涉及出单员和示例记录。
- 操作项为“列入”“不列入”，支持批量处理同类意见。
- 确认后立即重新计算当前期间，并将规则写入本地规则库。
- 保留确认人、确认时间、确认结果和规则版本。

### 历史期间页

- 按年度、月份和上传时间列出已保存结果。
- 可恢复查看当期总览和人员明细。
- 历史结果绑定当时的公式版本和规则版本，不因后续规则变更而静默改变。

## 5. 交互和状态

- 上传中：显示文件解析进度，禁止重复提交。
- 解析成功：展示文件期间、识别人数、待确认意见数量和即将计算的范围，用户确认后生成结果。
- 解析失败：明确指出缺少的字段、无法识别的人员或日期格式问题。
- 无匹配出单员：停止计算并提供异常记录下载或查看入口。
- 存在待确认意见：当前结果正常生成，但页面明显提示“待确认”，不把待确认记录计入下发清单。
- 重新上传同一期间：要求用户选择覆盖或另存为新版本，避免历史结果被无提示覆盖。
- 新上传清单：先展示与本地累计数据的合并预览，确认后才更新累计数据和当前结果。
- 同一条记录再次上传：按唯一性规则更新标准化记录，不重复增加总笔数和列入笔数；原始上传版本仍然保留。
- 点击排名行、低分人员或分布区间：进入对应筛选后的人员明细。

## 6. 视觉和响应式要求

- 采用浅灰中性背景、白色内容面板、深蓝主色，符合企业正规商务场景。
- 蓝色表示正常信息，绿色表示较好结果，黄色表示重点关注，红色表示严重异常。
- 不使用大面积渐变、装饰性插画或营销型首屏。
- 桌面端使用密集但清晰的分析布局，优先支持会议室大屏和常规办公显示器。
- 移动端将 KPI 改为单列，分析区域改为上下排列，表格保留横向滚动但不造成页面整体溢出。
- 颜色之外同时使用文字状态和分数，避免仅依赖颜色识别风险。

## 7. 验收标准

- 上传一份清单后，能够从“出单时间”生成年度和月份选项，并按选择刷新结果。
- 结果中只出现数据库出单员，组长不参与计算。
- 下发清单与已确认责任规则一致，未确认意见不计入当前结果。
- 每名人员的列入笔数能够复核到累计原始清单，总笔数能够复核到本地数据库的“非车保单 + 非车批改”月度记录，下发率和得分能够按公式重算。
- 总览页能直接看到整体结果、得分分布和低分人员。
- 可切换历史期间，历史结果和当时规则版本保持一致。
- 桌面和移动视图均无关键文字重叠、截断或横向页面溢出。

## 8. 待审阅项

本规格已锁定期间识别字段为“出单时间”，并新增本地原始数据持续积累与增量更新机制；同一条记录按“保单号优先、保单号为空时使用投保单号”判重，并保留上传版本用于追溯。其余口径沿用已确认的责任规则、人员范围和评分规则。用户审阅通过后，再进入技术方案和实现计划阶段。
