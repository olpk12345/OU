# 出单员下发率指标看板 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a local dashboard that accumulates uploaded underwriting lists, calculates the operator down-dispatch metric from the existing local database and confirmed responsibility rules, and provides period history, personnel drill-down, and pending-opinion confirmation.

**Architecture:** Add an isolated `downrate-dashboard` local Node application. It serves the dashboard and JSON API, stores immutable upload batches and versioned normalized rows in the existing `local-db/work.db`, and calls a small Python `openpyxl` parser for exact-header Excel extraction. Pure JavaScript domain modules read the existing database roster/workloads and confirmed rules, then save calculation snapshots so later uploads do not silently rewrite historical results.

**Tech Stack:** Node.js with built-in `http`, `node:sqlite`, `node:test`; Python 3.12 with `openpyxl`; vanilla HTML/CSS/JavaScript; Microsoft Edge driven by Playwright for visual smoke checks.

## Global Constraints

- Period detection uses source column `出单时间`, never the filename or Q/S column letters.
- Row identity uses `保单号`; when it is blank, use `投保单号`; when both are blank, keep the row as an unkeyed data-quality exception and never silently merge it.
- Personnel scope comes only from the local database operator roster; group leaders are excluded before aggregation.
- Source headers are matched by exact names `出单员`, `退回审核意见`, `提核退回标志`, `出单时间`, `保单号`, and `投保单号`.
- Do not use policyholder, insured, institution, business-agent, or other unrelated fields for responsibility decisions.
- Only confirmed operator-responsibility decisions count; unresolved opinions remain pending and are excluded from the score.
- Display `总笔数` as the local-database period sum of `非车保单 + 非车批改`; display upload row counts separately.
- Current score policy is `<=0.9%=100`, `0.9%-1.8%=99-90`, `1.8%-3%=89-60`, `3%-5%=59-1`, `>5%=0`.
- Keep each original workbook and upload version; never overwrite an original attachment.
- Run the application on port `54800` so it does not collide with the concept companion on port `54780`.
- The repository is not a Git worktree; do not add commit steps or mutate unrelated files.
